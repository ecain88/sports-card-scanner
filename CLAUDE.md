# Sports Card Scanner — Project Documentation

## Project Overview

A Progressive Web App (PWA) that analyzes sports trading cards for PSA-style centering and fetches eBay sale comparables. The user photographs a card, the app detects the outer card edge and inner print frame using GPT-4.1 Vision, computes left/right and top/bottom border ratios, maps them to a PSA centering grade, and surfaces eBay sold/active listings for that card.

## Architecture & Data Flow

### Scan Flow (Primary)

```
User uploads photo
      │
      ▼
ScanPage.tsx renders image in <canvas>
      │
      ├─ "Auto-detect borders" button
      │         │
      │         ▼
      │   cv.ts → calls convex action borders.detectBorders(base64Image)
      │         │
      │         ▼
      │   convex/borders.ts → GPT-4.1 Vision API
      │   Returns: { outer: Rect, inner: Rect, confidence, borderless }
      │         │
      │         ▼
      │   Overlays blue (outer) + green (inner) rectangles on canvas
      │
      ├─ Manual slider fine-tuning of border rectangles
      │
      ├─ Centering computed client-side
      │         │
      │         ▼
      │   centering.ts → pixel border widths → percentage splits
      │   psa.ts → worst axis → PSA grade (4–10)
      │   CenteringResult.tsx → displays grade + ratios
      │
      └─ eBay comps panel
                │
                ▼
          CompsPanel.tsx → convex action ebay.searchListings(query)
          convex/ebay.ts → eBay Browse API (OAuth client_credentials)
          Returns: active listings array
          + ebay.ts URL builders → deep links for sold comps
```

### Card Identification Flow

```
User uploads front [+ optional back] image
      │
      ▼
ScanPage → convex action vision.identifyCard(frontBase64, backBase64?)
      │
      ▼
convex/vision.ts → GPT-4.1 Vision API
Returns: { playerName, year, brand, set, cardNumber, variation, sport, team, grade, searchQuery }
      │
      ▼
saveCard mutation → stores in Convex DB (cards table)
```

### Authentication Flow

```
SignInForm.tsx → Convex Auth (email + password)
      │
      ├─ Sign in / Sign up → @convex-dev/auth Password provider
      │
      └─ Password reset → Resend API sends OTP email
```

## Database Schema (`convex/schema.ts`)

```typescript
cards: {
  userId: Id<"users">           // FK to auth users table
  playerName: string
  year: string
  brand: string
  cardSet: string
  cardNumber: string
  variation: string
  sport: string
  team: string
  grade: string
  searchQuery: string           // eBay-optimized search string
  storageId?: Id<"_storage">    // Convex file storage (card image)
  avgPrice?: number
  lowPrice?: number
  highPrice?: number
  totalSales?: number
  lastSalePrice?: number
  lastSaleDate?: string
  saleListings?: Array<{ title, price, currency, url }>
  centering?: {
    leftPct: number
    rightPct: number
    topPct: number
    bottomPct: number
    psaGrade: number
    verdict: string
  }
  isBorderless?: boolean
}
// index: "by_user" on ["userId"]
```

Auth tables are managed by `@convex-dev/auth` (users, sessions, accounts, verificationCodes, refreshTokens).


## Key Design Decisions

- **GPT-4.1 Vision for border detection** (not OpenCV.js): Replaced a 10 MB WASM bundle with a server-side Convex action. More robust on real card photos, zero browser bundle cost. See `docs/implementation-plans/centering-openai-vision.md`.
- **`anyApi` instead of generated types in web/**: Avoids the web build needing to reach `../convex/_generated`, making `web/` a self-contained Vercel deployment.
- **Pure client-side centering math**: Border pixel measurements → PSA percentage splits are computed locally (no network hop needed); only the initial border rect detection is server-side.
- **eBay sold comps as deep links**: Rather than parsing eBay's sold-listings API (requires special access), the app generates pre-filtered deep links to eBay search results.
- **Convex file storage for images**: Card images are uploaded directly to Convex storage via `generateUploadUrl` mutation, avoiding the need for a separate CDN.

---

## Architectural Constraints

- `web/` must remain fully self-contained — no imports from `../convex/` in the web build.
- Convex actions (`borders.ts`, `vision.ts`, `ebay.ts`) are the only place external API calls happen; never call OpenAI or eBay from the browser directly.
- Auth is always required for saving cards to the collection; scanning/centering works unauthenticated.
